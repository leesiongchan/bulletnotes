# Antinote UI and Scratchpad Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Apply the inspected Antinote interface and an ordered, automatically synced scratchpad stack to BulletNotes.

**Architecture:** Persist connection-scoped ordering metadata beside the existing pages table. Feed a coalesced metadata-only snapshot into the coordinator, and route stack navigation through its revision checks plus an explicit metadata durability barrier. Restyle the existing Slint components and native hover adapter around those actions.

**Tech Stack:** Existing Rust 1.99.1 toolchain, Slint 1.18.1, SQLite/rusqlite, Tokio, Jiff 0.2.38, public AppKit window APIs; existing dependencies only.

**Spec:** [Approved design](../specs/2026-10-19-antinote-ui-ux-design.md).

## Global Constraints

- The scratchpad stack contains Markdown pages below the exact `Quick Notes/` folder in the active connection.
- Retain the existing resizable native window and its 505 by 552 logical-pixel default, with a 400 by 440 minimum.
- Command+N creates a scratchpad; nonempty notes synchronize automatically through the existing outbox; deletion stays manual and recoverable.
- Previous means the adjacent older scratchpad; Next means the adjacent newer scratchpad. Position is `1 of N` for newest.
- Revealing either overlay never moves, rewraps, or replaces editor text.
- No production database is opened or migrated during development verification. Use temporary databases and generated notes.
- Preserve the supported Slint editor, source bytes, atomic settings saves, and guarded synchronization. Native translucency and inline Markdown coloring remain deferred.
- Keep diagnostics typed and local; exclude note bodies, titles, paths, and credentials.

## Review Focus

- Restoring a page replaces its SQLite row: order must survive Trash, row replacement, restart, and restoration to an alternate path (Task 1).
- Clock rollback, invalid generated dates, daylight-saving transitions, and timezone changes must not reorder admitted entries or prevent a new local note entering first (Task 1).
- Connection A → B → A and rapid repeated navigation must reject old snapshot, barrier, page-load, and recovery completions (Tasks 2 and 3).
- A clean text buffer can still have failed position metadata: leaving the editor must wait for that metadata and retain the buffer on failure (Task 2).
- A catalogue-only destination is different from a missing page, and a loading stack is different from an empty stack; preserve the editor during offline/error paths (Tasks 2 and 3).

## Existing editor limitation

Read [selection-api.md](../../validation/selection-api.md) before execution. The current editor can restore a supplied UTF-8 anchor/caret and scroll target, but production code cannot obtain every exact directional selection through supported Slint APIs. The recorded user decision keeps Slint and skips AppKit editor prototyping. Test restoration of known observations and retention of the live editor across auxiliary views; do not invent offsets, use private properties, replace the editor, or call synthetic restoration proof of complete native capture. Exact cross-page/relaunch selection capture remains an open final-product requirement and must appear in the final evidence report.

## File responsibilities

- `migrations/008_scratchpad_stack.sql`, `src/store/scratchpads.rs`: durable ordering/admission and active metadata queries.
- `src/app/scratchpads.rs`: pure ordered-stack destinations and position calculations.
- `src/app/coordinator.rs`: generation-checked transitions and their durability requirements.
- `src/app/local_ui/scratchpads.rs`, existing effects/bindings/presentation: coalesced snapshot loading and Slint integration.
- Existing Slint components and `src/platform/window_chrome.rs`: appearance, interaction geometry, keyboard access, and native traffic lights.
- Existing generated-note fixtures, focused regression files, and one validation report: repeatable evidence without user notes.
